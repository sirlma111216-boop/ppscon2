# 내일을 여는 상자 — 제작 명세

작성 기준: 2026-11-04 · 대상: 1인 개발자와 AI 코딩·그래픽·사운드 보조 · 플랫폼: PC 웹

이 문서는 구현할 게임의 기준이다. 제안 단계의 무한 경영, 직접 운송 조작, 대규모 도시 건설은 구현하지 않는다. 숫자와 시설 상황은 게임을 위해 만든 가상 데이터다. 실제 입찰·계약·검사 절차, 법정 기준, 조달가격을 재현하는 법률 시뮬레이터가 아니다.

## 1. 제작 목표와 핵심 판단

한 장의 한국 동네 디오라마에서 공공기관의 필요를 읽고 적합한 공급안을 비교해, 주민이 실제로 이용하는 변화까지 확인하는 생활 문제 해결 퍼즐을 만든다.

**가장 중요한 플레이는 ‘어떤 이용자에게 어떤 기능이 필요한지 판단하는 것’이다. 설치 칸 맞추기는 그 선택을 실행할 수 있는지 확인하는 두 번째 제약이다.** 물건을 운반하거나 건물 운영 수익을 늘리는 게임으로 만들지 않는다.

- 임무 3개, 시설 4곳, 임무당 요구 2개.
- 목표 첫 플레이 시간 10~14분. 12분 안팎을 기본으로 하고 18분을 채우려고 반복 작업을 넣지 않는다.
- 계획 중 시간은 흐르지 않는다. 확정한 계획의 실행 연출은 임무당 총 24초 이하이다. 선택·관찰 패널을 읽는 시간은 별도이며 타이머가 없다.
- 로그인, 결제, 서버 저장, 실시간 생성형 AI, 외부 API 키가 필요 없다.
- 실제 로고보다 시민과 물건의 사용 장면이 중심이다. 조달의 역할은 구매 판단과 결과의 연결에서 드러나야 한다.

### 역할을 화면과 대사에서 분리한다

| 주체 | 게임에서 하는 일 | 하지 않는 표현 |
|---|---|---|
| 학교·도서관·주민센터 등 수요기관 | 이용자의 필요, 필수 기능, 사용 시작 시점을 제시하고 사용 결과를 알려준다 | 조달청이 모든 기관의 행사와 운영을 대신 결정한다는 설명 |
| 플레이어: 조달지원 담당 | 같은 기준으로 공급안을 비교하고, 예산·준비 일정 안에서 구매·공급 계획을 돕고 결과를 확인한다 | 시장, 택배 기사, 제조업자, 모든 공공시설의 관리자라는 설정 |
| 공급자 | 선택된 물품을 공급하고 설치·설정·개선에 참여한다 | 플레이어가 직접 물건을 생산하거나 로봇을 발명했다는 연출 |
| 이용자 | 기능을 사용하고 변화와 불편을 보여준다 | 인기투표로 공급자를 결정하거나 특정 주민의 가치를 점수로 매기는 설정 |

시작 화면의 짧은 안내: “공공기관의 필요를 적합한 구매와 공급으로 연결하는 게임입니다. 실제 조달 절차를 쉽게 이해하도록 단순화했습니다.”

## 2. 맵, 화면, 조작

고정 시점의 한 장면에 네 시설을 배치한다. 시설 ID는 다른 코드와 에셋 명세에서도 일관되게 사용한다.

| ID | 시설 | 핵심 변화 |
|---|---|---|
| `library` | 작은 동네 도서관 | 오전 독서 공간이 오후 프로그램 공간으로 실제 전환된다 |
| `school` | 학교와 지역공유 학습 공간 | 높이와 무릎 공간을 맞춘 책상에서 서로 다른 이용자가 함께 배운다 |
| `community` | 주민센터 | 처음 온 주민이 안내 도구를 사용하고 피드백이 반영된다 |
| `park` | 공원 | 안내가 명확해지고 주민의 쉼·행사 공간이 준비된다 |

데스크톱 기본 구성은 상단의 임무·예산, 중앙 디오라마, 우측 요구·비교 패널, 하단 6칸 준비 일정이다. 작은 화면에서는 패널이 겹치지 않게 접거나 아래로 내려간다. 숫자와 조작 영역을 배경 이미지에 넣지 않는다.

- 기본 조작: 시설 선택 → 요구 읽기 → 공급안 비교 → 카드 선택 → 설치 시작 칸 선택.
- 드래그는 보조 조작이다. 클릭 후 칸 선택만으로 모든 행동을 완료할 수 있어야 한다.
- 키보드로 시설·카드·칸·버튼에 접근하고 Enter/Space로 선택할 수 있다.
- 호버는 추가 설명일 뿐, 필수 정보를 호버에만 숨기지 않는다.
- 계획 변경은 확정 전 자유롭다. 잘못 놓은 카드는 즉시 되돌릴 수 있다.
- 색과 함께 아이콘·문구를 사용한다. 빨강/초록만으로 판정하지 않는다.

## 3. 첫 90초의 실제 경험

아래 시간은 목표 흐름이며 강제 시간 제한이 아니다. 느리게 읽는 이용자에게 불이익을 주지 않는다.

| 경과 | 화면·행동 | 알아야 할 사실 |
|---|---|---|
| 0~10초 | 종이 무대 같은 동네가 열리고 시설의 생활음이 작게 들린다. 시작 버튼 한 개 | 내가 바꾸게 될 동네가 보인다 |
| 10~25초 | 도서관의 오전 독서 자리가 보이지만 오후 프로그램을 할 공간이 부족하다. “오전에는 책을 읽고, 오후에는 이 자리를 넓게 쓰고 싶어요.” | 물건 이름보다 생활 공간의 필요가 먼저다 |
| 25~45초 | `changes_layout`, `compact_storage` 두 조건을 그림으로 보여준다. 이용자가 L0/L1/L2의 사용 미리보기를 열어 조건을 살핀다. L0도 비교·미리보기 가능하며 처음부터 정답처럼 회색 처리하지 않는다 | 물건이 공간을 어떻게 바꾸는지 보고 조건을 확인한다 |
| 45~65초 | L1의 접어 좁게 보관하기와 L2의 바퀴로 모듈을 이동하기를 비교한다. 선택한 안의 비용·도착·준비 길이가 반영된다. 불충족 안을 고르면 이유가 나타나며 실행 확정은 막힌다 | 적격 대안도 생활상의 장점과 준비 조건이 서로 다르다 |
| 65~80초 | 학교의 높이 조절·무릎 공간 요구와 빠른 마감이 등장한다. 좁은 자리에 맞는 S1과 재료를 펼칠 수 있는 S2를 미리 본다 | 다른 기관의 이용자에게는 다른 기능이 필요하다 |
| 80~90초 | 준비 칸 충돌 또는 정상 배치를 즉시 피드백. “바꾸기”와 “다른 공급안 보기”가 보인다 | 수정 비용 없이 계획을 고칠 수 있다 |

튜토리얼은 첫 임무에만 겹쳐 표시한다. 첫 90초 안에 적어도 하나의 실제 선택과 그에 따른 비용·일정 변화가 일어나야 한다. 오프닝 영상으로 90초를 소비하지 않는다.

## 4. 공통 규칙 — 구현 시 바꾸지 말 것

### 4.1 요구 적합성이 먼저다

각 요구에는 안전 확인 상태와 필수 기능 태그가 있다. 모든 제시안은 비교 열기·사용 미리보기·조건 확인이 가능하다. 이용자가 조건을 살펴보고 안을 고르는 것이 행동이며, 부적격 안을 처음부터 숨기거나 비활성화해 정답을 알려주지 않는다.

부적격 안도 검토용으로 잠정 선택할 수 있다. 그때 불충족 기능 또는 안전확인 상태와 실제 사용상 문제를 표시하고 **구매·실행 확정을 차단**한다. 잠정 선택은 거래 성립·설치 실행을 뜻하지 않는다. 필수 조건을 무시하고 예산을 아끼는 확정 경로는 존재하지 않는다. 조건 검토는 공급안의 정보와 미리보기를 살펴보는 자연스러운 조작이며, 별도의 반복 체크박스 퀴즈가 아니다.

적격 카드 두 개는 동일한 비교 항목을 사용한다. 브랜드 친분, 유명도, 주민 인기, 임의의 숨은 호감도로 선택 결과가 달라지지 않는다. 실제 업체명·실제 제품 성능을 빌려오지 않는다.

필수 기능을 갖춘 공급안끼리는 비용과 준비 조건이 다르다. 비싼 안이 무조건 정답이 아니며, 가장 저렴한 안을 고르는 것 자체가 공정성을 뜻하지도 않는다. 기능 태그는 게임의 가상 요구사항이며 공인 인증·법정 규격을 의미하지 않는다.

### 4.2 3일 × 2칸의 준비 일정

| 내부 슬롯 | 표시 |
|---|---|
| 1 | 1일차 오전 |
| 2 | 1일차 오후 |
| 3 | 2일차 오전 |
| 4 | 2일차 오후 |
| 5 | 3일차 오전 |
| 6 | 3일차 오후 |

시간은 실제 소요시간을 측정한 값이 아닌 게임 단위다. 배경 안내에 “준비 일정을 단순화한 가상 시간”이라고 설명한다. 임무 사이로 미사용 예산·재고·일정은 이월하지 않는다.

- 공유되는 현장 설치·설정 지원 용량은 슬롯당 작업 1개이다.
- 카드의 `readySlot`은 배송이 끝나 설치를 시작할 수 있는 첫 슬롯이다. 배송차 이동은 이 용량을 사용하지 않는다.
- 설치는 `duration`개의 연속 슬롯을 사용한다. 예: 시작 2, 길이 2이면 2와 3을 사용한다.
- 완료 슬롯은 `start + duration - 1`이다.
- 시작은 `readySlot` 이상이어야 한다. 완료는 요구의 `deadline` 이하여야 한다.
- 임무 2의 개선·재확인은 초기 시범 설치 완료 **다음 슬롯부터** 배치할 수 있다. 같은 슬롯의 즉시 개선 완료는 불가하다.
- 작업 분할, 시설 간 실시간 운송, 물품 수량 재분배, 무작위 배송 사고는 없다.
- 타이머가 실행되기 전에 모든 예산·슬롯·기능·납기 제약을 검증한다. 실행 도중 무작위로 계획을 망치지 않는다.

### 4.3 예산

비용의 단위는 **게임 예산점**이며 원화·실제 조달가격이 아니다. 한 임무의 총비용은 선택한 공급안 비용 합계에 명시된 필수 개선 예약비를 더한 값이다. 숨은 세금·배송료·랜덤 비용은 없다.

예산 초과는 확정 차단 사유다. “예산을 8점 넘었습니다. 같은 필수 조건을 충족하는 다른 안을 비교해 보세요.”처럼 무엇을 바꿀 수 있는지 설명한다.

### 4.4 비교 이유

처음 공급안을 고를 때 요구 태그와 근거를 연결하는 짧은 설명을 자동으로 보여준다. 결과 화면에는 선택 근거가 한 문장으로 남는다. 예: “접어서 좁은 수납 공간에 넣을 수 있어, 오전 독서 자리를 오후 프로그램 공간으로 바꿀 수 있습니다.” 이는 선택한 안의 기능 근거이며 사용자의 마음속 동기를 추정하는 문구가 아니다.

두 적격 대안의 비교 정보가 함께 표시되거나 두 안의 미리보기를 각각 연 경우 `comparisonReviewed`를 자동 기록한다. 사용자의 의도적 비교 열기·미리보기 조작을 기록하며, 최초 화면에 목록이 로드됐다는 이유만으로 완료하지 않는다. ‘읽었어요’, ‘이 기준으로 비교했어요’ 같은 추가 확인 버튼·반복 클릭 게이트는 만들지 않는다. 선택 근거와 조건 판정은 기존 비교·선택 화면에 자동으로 나타난다.

## 5. 임무 데이터

아래 수치가 구현의 기본 데이터이다. 비용·준비일·설치 길이를 바꾸면 마지막의 전수 검산을 다시 수행해야 한다. 모든 적격 카드의 `safetyPass`는 `true`이고 필수 태그를 모두 갖는다. 부적격 제시안도 비교·미리보기·잠정 선택 목록에 남는다. 적격 공급안 전수 검산과 실제 실행 확정 대상에서만 제외한다. `displayOptions`와 `eligibleOptions`를 같은 목록으로 구현하지 않는다.

### 임무 1 — 내일의 독서 공간

**수요와 이야기:** 도서관은 오전 독서와 오후 프로그램에 같은 방을 쓰고 싶다. 학교는 서로 다른 이용자에게 맞춰 높이를 조절하고 무릎 공간을 확보할 학습 자리가 필요하며 사용 시작이 더 빠르다. 플레이어는 공간 전환과 학습 자세라는 서로 다른 필요를 구분해 구매와 준비를 돕는다.

- 예산: `82`
- 요청 1: 도서관 공간 전환용 활동 테이블 묶음. 필수 태그 `changes_layout`, `compact_storage`. 완료 마감 슬롯 `6`.
- 요청 2: 학교 높이 조절 학습 책상 묶음. 필수 태그 `adjustable_height`, `usable_knee_space`. 완료 마감 슬롯 `3`.
- 각 카드의 수량은 해당 요구를 충족하는 묶음으로 이미 정해져 있다. 수량 입력 기능은 없다.

| 공급안 ID | 시설·가상 공급안 | 비용 | 준비 완료 `readySlot` | 설치 `duration` | 이용 모습·비교 설명 |
|---|---|---:|---:|---:|---|
| L1 | library / 접이식 활동 테이블 | 36 | 1 | 2 | 접어서 더 좁은 공간에 보관하는 장점. 현장 배치·확인에 두 칸이 필요하다 |
| L2 | library / 이동 모듈 테이블 | 48 | 3 | 1 | 바퀴로 모듈을 빠르게 옮겨 배치를 바꾸는 장점. 중첩·모아두기로 기본 수납 조건을 충족하지만 L1보다 수납 폭이 크다. 도착은 늦고 준비는 한 칸이다 |
| S1 | school / 소형 수동 높이 조절 책상 | 34 | 2 | 2 | `compact`: 좁은 자리 배치에 유리하나 학습 재료를 펼칠 상판은 작다. 수동 높이 설정·확인으로 두 칸이 필요하다 |
| S2 | school / 넓은 높이 조절 책상 | 42 | 3 | 1 | `wide`: 재료를 넓게 펼치기 좋지만 자리 면적을 더 쓴다. 높이·배치 확인은 한 칸이며 비용이 높다 |

L1/L2 모두 배치를 바꾸고 정해진 수납 공간에 들어가는 최소 조건을 충족한다. S1/S2 모두 높이 조절과 무릎 공간을 갖추며 학교의 기본 배치 가능 범위 안에 들어간다. `compact`와 `wide`는 상대적 장점이며 어느 한쪽이 필수 안전·기능 조건을 덜 충족한다는 뜻이 아니다. 책상 면적·높이의 법정 수치를 임의로 만들어 넣지 않는다.

부적격 제시안 `L0`: 접거나 모아두기 어려운 고정형 큰 테이블. 미리보기에서는 오후 프로그램을 위한 빈 공간이 남지 않는다. 잠정 선택하면 “배치 전환·수납 요구를 충족하지 못해 이 계획을 확정할 수 없어요.”를 표시한다. `S0`: 높이를 바꿀 수 없는 고정형 책상. 다양한 이용자에게 높이를 맞추는 모습을 보여줄 수 없으며, 선택하면 높이 조절 조건 미충족을 설명한다. 두 안은 처음부터 숨기거나 회색 정답 힌트로 만들지 않는다. 안전확인 미충족의 공통 예시도 자료 확인·미리보기는 허용하되 거래·실행 확정은 불가하다.

검산된 실행 가능 조합과 예시:

| 선택 | 총비용 | 예시 설치 슬롯 | 결과 |
|---|---:|---|---|
| L1 + S1 | 70 | 학교 2~3, 도서관 4~5 | 모두 충족, 예산 12 남음 |
| L1 + S2 | 78 | 도서관 1~2, 학교 3 | 모두 충족, 예산 4 남음 |
| L2 + S1 | 82 | 학교 2~3, 도서관 4 | 모두 충족, 예산 전액 사용 |
| L2 + S2 | 90 | 시간 배치는 가능 | 예산 8 초과로 확정 불가 |

**변화:** 도서관의 오전 독서 배치가 오후 프로그램 배치로 실제 바뀐다. L1은 테이블을 접어 좁은 수납 구역에 넣고 열린 바닥을 확보한다. L2는 바퀴 달린 모듈을 이동·모아 프로그램용 배치로 빠르게 전환한다. 같은 성공 연출을 색만 바꿔 재생하지 않는다. 학교에서 S1은 소형 책상 사이의 여유 있는 이동 공간과 수동 높이 조절을, S2는 넓은 상판에 학습 재료를 펼치고 높이를 맞춰 사용하는 모습을 보여준다. 접힘·걸쇠 확인음 또는 작은 바퀴 소리, 높이 조절음과 종이·필기 도구 소리가 선택에 맞춰 더해진다.

### 임무 2 — 첫 구매, 첫 사용, 한 번 더 확인

**정책 중심:** 혁신제품을 능력치가 높은 상위 아이템으로 표현하지 않는다. 공공현장의 필요 → 첫 공공구매·시범사용 기회 → 이용 관찰 → 공급자의 개선 → 재확인을 플레이로 연결한다. 아래 제품과 사용 관찰은 창작이며 실제 지정 제품이 아니다.

- 예산: `78`
- 요청 1: 주민센터의 처음 온 이용자를 위한 안내 도구. 필수 태그 `text_and_audio`, `no_personal_data_collection`. 초기 설치 완료 마감 `4`.
- 요청 2: 공원 행사 장소를 찾는 안내판. 필수 태그 `readable_symbols`, `relocatable`. 완료 마감 `6`.
- 주민센터는 사용 관찰 후 개선·재확인 `1칸`, 비용 `8`을 반드시 예약한다. 초기 설치와 별개 작업이며 마감은 슬롯 `5`.
- 초기 계획 화면에서도 비용 `8`과 후속 작업을 이미 보여준다. 나중에 숨겨진 비용으로 나타나면 안 된다.

| ID | 시설·가상 공급안 | 비용 | readySlot | duration | 특징 |
|---|---|---:|---:|---:|---|
| I1 | community / 현장 설정형 안내 도구 | 42 | 1 | 2 | 초기 설정 시간이 길고, 실제 이용 문구를 관찰해 개선한다 |
| I2 | community / 사전 설정형 안내 도구 | 54 | 2 | 1 | 초기 설정 시간이 짧고, 실제 이용 화면의 구성을 관찰해 개선한다 |
| G1 | park / 조립형 이동 안내판 | 16 | 1 | 2 | 일찍 도착하고 저렴하지만 조립·설정에 두 칸이 필요하다 |
| G2 | park / 완성형 이동 안내판 | 24 | 3 | 1 | 늦게 도착하지만 완성 상태로 제공된다 |
| R1 또는 R2 | community / 관찰 후 개선·재확인 | 8 | 초기 설치 완료 다음 칸 | 1 | 모든 계획에서 필수 예약, 완료 마감 5 |

G1은 저렴하고 일찍 도착하지만 설치가 길다. G2는 비싸고 늦게 도착하지만 설치가 짧다. 두 적격 대안에 실제 시간·비용 차이가 있으며, 어느 한 안을 모든 면에서 우월하게 만들지 않는다.

탈락 예시 `I0`: 음성만 제공하여 글자 안내 요구를 충족하지 못하는 장치. `G0`: 옮길 수 없는 안내판. 실제 제품의 품질이나 장애인 접근성 법정 적합성을 판정하는 설정이 아니다.

#### 필수 관찰·개선 상태

| 선택 | 최초 관찰 | 개선 선택지 | 유효한 개선·재확인 |
|---|---|---|---|
| I1 | 이용자가 첫 화면의 긴 문장을 다시 읽는다 | 첫 문장·단계 수 간소화 / 외관 색만 변경 | 문장·단계를 간소화하고, 이용자가 다음 단계로 진행하는지 확인 |
| I2 | 이용자가 많은 버튼 사이에서 필요한 메뉴를 찾는다 | 주요 메뉴 배치 단순화 / 배경 장식 추가 | 메뉴 구성을 단순화하고, 필요한 메뉴를 찾는지 확인 |

선택지 문구에 ‘정답’ 표시를 먼저 하지 않는다. 잘못된 개선을 고르면 “관찰한 문제는 문구/메뉴 찾기였습니다. 이 변경으로 해결되는지 다시 생각해 보세요.”를 보여준다. 시간·예산을 추가 소모시키거나 나쁜 점수를 영구적으로 남기지 않는다. 재선택 후 예정된 1칸에서 개선을 완료한다.

안전·필수 기능의 미충족을 시민에게 시험하는 이야기가 아니다. 기본 조건을 갖춘 도구의 사용 경험을 개선한다. 과장된 성공률·실제 성능 수치를 표시하지 않는다.

| 선택 | 초기비 + 개선비 + 안내판 | 예시 설치·재확인 슬롯 | 결과 |
|---|---:|---|---|
| I1 + G1 | 42 + 8 + 16 = 66 | 안내판 1~2, 초기 설치 3~4, 개선·재확인 5 | 모두 충족 |
| I1 + G2 | 42 + 8 + 24 = 74 | 초기 설치 1~2, 개선·재확인 3, 안내판 4 | 모두 충족 |
| I2 + G1 | 54 + 8 + 16 = 78 | 안내판 1~2, 초기 설치 3, 개선·재확인 4 | 모두 충족 |
| I2 + G2 | 54 + 8 + 24 = 86 | 시간 배치는 가능 | 예산 8 초과 |

예약한 재확인 칸이 초기 설치보다 앞서거나 같은 칸이면 확정할 수 없다. 관찰·개선·재확인 없이 주민센터 요구를 완료 처리할 수 없다.

**변화:** 처음 멈칫하던 이용자가 안내 도구로 목적지를 찾아 움직인다. 장식용 성공 폭죽보다 망설임이 해소되는 작은 동작, 안내 확인음, 문 여닫는 소리가 보상이다.

### 임무 3 — 모두의 행사를 준비하는 기준

최종 임무에는 네 시설이 한 동네로 보인다. 앞선 두 임무에서 고른 도서관 가구와 개선을 마친 주민센터 안내 도구의 사용 상태를 유지한다. 이번에 새로 구매할 두 묶음은 학교·공원용이다. 엔딩 전에는 네 곳을 차례로 비춰, 어디서 어떤 필요가 어떤 기능으로 해결됐는지 짧게 되짚는다. 전체 동네를 보여주기 위해 이미 해결한 기관의 구매를 또 시키거나 새 퍼즐을 추가하지 않는다.

**수요:** 학교의 지역공유 학습 자리와 공원 행사를 각각 준비한다. 학습 자리는 임무 1과 별도의 구매 수요이며, 사용 시점과 예산이 다른 상황에서 같은 기능 기준을 적용한다. 인기 높은 시설만 지원하거나 업체 친분으로 결정하지 않는다.

- 예산: `80`
- 요청 1: 공원 이동형 쉼·그늘 공간 묶음. 필수 태그 `provides_shade`, `relocatable`. 완료 마감 `5`.
- 요청 2: 학교 지역공유 학습 자리의 높이 조절 책상 묶음. 필수 태그 `adjustable_height`, `usable_knee_space`. 완료 마감 `4`.
- 임무 1과 같은 책상 기능 태그·이미지 자산·비교 구조를 사용한다. 가상 구매는 별개이며, 앞에서 익힌 기준을 다른 사용 시점에 적용하는 것이지 이미 산 물건을 순간 이동시키는 것이 아니다.

| ID | 시설·가상 공급안 | 비용 | readySlot | duration | 비교 설명 |
|---|---|---:|---:|---:|---|
| P1 | park / 현장 조립형 쉼 공간 | 40 | 2 | 2 | 두 칸이 필요하지만 다른 시설에 쓸 예산을 남긴다 |
| P2 | park / 사전 조립형 쉼 공간 | 52 | 4 | 1 | 도착은 늦지만 현장 작업이 짧다 |
| E1 | school / 공유학습용 소형 수동 높이 조절 책상 | 28 | 1 | 2 | `compact`: 좁은 자리 배치에 유리하며 상판은 작다. 일찍 도착하지만 설정·확인 두 칸이 필요하다 |
| E2 | school / 공유학습용 넓은 높이 조절 책상 | 36 | 2 | 1 | `wide`: 재료를 넓게 펼치기 좋지만 자리 면적을 더 쓴다. 현장 준비는 한 칸이고 비용이 높다 |

부적격 제시안 `P0`: 그늘 기능을 제공하지 못하는 장식물. `E0`: 높이 조절 기능이 없어 다른 이용자에게 맞추지 못하는 고정형 책상. 비교·사용 미리보기·잠정 선택은 가능하고, 해당 조건이 충족되지 않는 이유를 보여준 뒤 확정을 차단한다. 위험한 그늘막·안전검사 생략을 거래할 수 있는 경로는 없다.

| 선택 | 비용 | 예시 슬롯 | 결과 |
|---|---:|---|---|
| P1 + E1 | 68 | 학교 1~2, 공원 3~4 | 모두 충족 |
| P1 + E2 | 76 | 학교 2, 공원 3~4 | 모두 충족 |
| P2 + E1 | 80 | 학교 1~2, 공원 4 | 모두 충족 |
| P2 + E2 | 88 | 시간 배치는 가능 | 예산 8 초과 |

**변화:** 학교의 공유학습 자리에서 이용자에게 책상 높이를 맞춘다. E1은 좁은 공간의 여유 있는 배치, E2는 넓은 상판의 재료 전개를 보여준다. 공원에서는 주민이 준비된 그늘에 앉는다. 책상 높이 조절·종이·필기 소리와 공원의 생활음이 더해져 마지막에는 작은 동네의 소리가 완성된다. 실제 음향은 소리 크기가 아닌 공간감과 질감으로 변화를 전달한다.

## 6. 상태와 판정

일반 임무 상태:

`briefing → planning → readyToConfirm → executing → verifying → result`

임무 2의 실행·검증에는 다음 상태를 포함한다:

`pilotInstalled → observationShown → improvementChosen → rechecked`

관찰 패널을 읽는 동안 애니메이션 시간은 멈춘다. 페이지의 재생 상태와 정책 학습 진행 상태를 하나의 타이머로 관리하지 않는다.

### 실행 전 검증

1. 두 요구에 적격 공급안이 하나씩 선택됐는가?
2. `safetyPass`와 모든 필수 기능이 충족되는가?
3. 총비용과 필수 예약비가 예산 이내인가?
4. 작업 시작이 도착 이후이고, 설치는 연속 칸인가?
5. 작업 칸이 겹치지 않는가?
6. 각 작업이 마감 이내에 완료되는가?
7. 임무 2의 개선·재확인이 초기 설치 이후이며 슬롯 5까지 완료되는가?

어느 하나가 실패하면 실행 버튼을 비활성화하고, 상단에는 첫 번째 구체 오류를 보여준다. 오류가 있는 카드·슬롯에서도 해당 이유를 확인할 수 있어야 한다. ‘실행 불가’ 한 문장만 표시하지 않는다.

### 승리 조건

- 일반 임무: 두 요구의 필수 기능·예산·일정이 충족되고, 결과 확인을 완료하면 성공.
- 임무 2: 위 조건에 관찰·적합한 개선·재확인이 추가된다.
- 캠페인: 3개 임무 성공. 선택했던 공급안과 이용 변화를 요약하고 ‘다시 비교해 보기’를 제공한다.
- 계획 수정·처음 읽는 속도·음소거·키보드 사용으로 점수를 깎지 않는다.
- 실행 후 실패를 무작위로 발생시키지 않는다. 실패는 계획 단계의 수정 가능한 상태이다.

| 수요 충족 | 60 | 두 요구 각각 30. 적격 기능과 해당 설치 완료를 확인 |
| 같은 기준으로 비교 | 20 | 두 요구 각각 10. 두 적격 대안을 본 상태를 자동 기록하고 선택 근거를 표시. 추가 확인 버튼 없음 |
| 사용 결과 확인 | 20 | 두 요구 각각 10. 일반 요구는 이용 확인, 혁신 요구는 관찰·개선·재확인까지 완료 |

안전·예산·납기는 점수로 상쇄할 수 없는 실행 조건이다. 더 싸게 샀다는 이유만으로 추가 점수를 주지 않는다. 여러 유효 계획이 모두 100점을 받을 수 있다. 이 점수는 공공서비스 성과나 실제 기관 평가가 아니며 학습 완료 표시이다.

## 8. 그래픽 방향 — 한국 동네 리소그래프 종이 무대

### 원하는 인상

한국의 소규모 공공시설과 생활 골목을 바탕으로, 색판을 겹쳐 인쇄한 리소그래프 질감과 손으로 자른 종이 무대의 깊이를 결합한다. 절제된 잉크 번짐, 작은 색판 어긋남, 거친 종이 결을 사용한다. 가독성이 떨어질 정도의 노이즈는 금지한다.

피해야 할 인상: 광택 있는 장난감 3D 마을, 보라·파랑 네온 대시보드, 익숙한 AI 생성 등각투영 도시 콜라주, 과한 보케, 의미 없는 반짝이, 모든 건물에 같은 둥근 모서리를 붙인 모바일 광고풍.

### 이미지가 맡을 것과 DOM이 맡을 것

- 배경 골목, 건물 외관, 나무, 종이 물품, 주민, 변화 오버레이는 실제 이미지 레이어로 구성한다. CSS 도형만으로 완성했다고 하지 않는다.
- 시설은 같은 시점·광원·윤곽 두께·색판 팔레트를 공유한다. 카메라는 회전하지 않는다.
- 시설은 `base → prepared → in_use` 상태를 이미지나 투명 오버레이로 표현한다. 모든 변화에 별도 전체 배경을 생성하지 않는다.
- 이미지 안에 제목, 간판 글자, 숫자, 가격, 설명, 버튼을 생성하지 않는다. **모든 읽어야 하는 한글은 DOM 텍스트**로 배치한다.
- 상자를 클릭하면 이미지가 아니라 명확한 DOM 버튼이 반응해야 한다. 장식 이미지에는 적절한 대체 설명 또는 장식 처리한다.
- 주민은 작은 실루엣·종이 인형 같은 형태로, 세 가지 기본 유형과 소수의 반복 동작만 사용한다. 얼굴 클로즈업·립싱크는 없다.
- 이미지 생성의 세부 모델명·서비스는 이 명세가 강제하지 않는다. 에셋 출처와 AI 사용 과정은 제작 기록에 남긴다.

필수 시각 피드백은 모든 제시안의 사용 미리보기, 조건 검토·잠정 선택에 따른 적격/불충족 이유, 일정 유효 영역, 물품이 쓰이는 행동 변화다. 부적격 안을 처음부터 비활성화해 답을 알려주지 않는다. 도서관 배치가 실제로 바뀌지 않거나 학교 책상 높이·사용 모습이 달라지지 않으면, 정적 예쁜 지도가 있어도 미완성이다.

## 9. 사운드와 동작

소리는 게임 진행 상태를 들려주는 보상이다. 사운드를 끄면 정보가 사라지지 않아야 한다.

- 시작 버튼의 사용자 동작 후에만 오디오를 재생한다. 브라우저 자동재생 차단을 피한다.
- 배경음은 따뜻하고 소박한 짧은 루프. 장시간 계획 중에도 피로하지 않게 한다.
- 클릭·카드 선택·종이 펼침·배치 확인은 짧고 절제된 소리로 통일한다.
- 시설별 생활음 레이어: 도서관 접이 테이블의 접힘·걸쇠 또는 모듈 바퀴와 오전 독서에서 오후 프로그램으로 달라지는 사람 기척, 학교 책상 높이 조절·종이·필기 소리, 주민센터 안내 확인음·문, 공원 나뭇잎·멀리 있는 생활 기척.
- 성공 연출은 큰 팡파르를 반복하지 않는다. 시설의 기능이 살아나는 소리가 더해지는 것을 핵심 보상으로 쓴다.
- 음량 슬라이더, 전체 음소거, 음량 설정 유지가 필요하다. 잘림·갑작스러운 최대음량·클리핑이 없어야 한다.
- 저동작 설정에서는 이동·등장 애니메이션을 짧은 페이드 또는 즉시 상태 전환으로 대체한다.
- 실행 연출 건너뛰기와 결과 확인은 분리한다. 건너뛰어도 사용 확인 패널을 볼 수 있다.

## 10. 구현 범위와 데이터 구조

장면·대사·공급안을 코드 곳곳에 하드코딩하지 않는다. 정적 데이터와 순수 판정 함수로 분리한다. 아래는 개념 인터페이스이며 특정 프레임워크를 강제하지 않는다.

```ts
type FacilityId = 'library' | 'school' | 'community' | 'park';
type Requirement = {
  id: string;
  facilityId: FacilityId;
  needText: string;
  requiredFeatures: string[];
  deadline: number;
  optionIds: string[];
};
type SupplyOption = {
  id: string;
  cost: number;
  readySlot: number;
  duration: number;
  safetyPass: boolean;
  features: string[];
  tradeoffText: string;
};
type PlannedJob = {
  id: string;
  requirementId: string;
  startSlot: number;
  duration: number;
  afterJobId?: string;
  deadline: number;
};
```

`getEligibleOptions`, `getTotalCost`, `getOccupiedSlots`, `validatePlan`, `getCompletionState`는 적격 판단, 총비용, 점유 칸, 계획 검증, 완료 상태 계산을 부작용 없이 수행한다. 화면 표시와 실행 확정 시 같은 함수를 사용한다. `getEligibleOptions`의 결과로 비교 카드 전체를 필터링하지 않는다. 전체 제시안은 열어볼 수 있고, 잠정 선택의 `eligibilityIssues`가 비어 있을 때만 실행 가능한 계획으로 반영한다.

진행 저장은 로컬 저장소로 충분하다. 새로 시작/임무 다시하기 시 예산·선택·슬롯·관찰 상태·사운드 상태가 서로 섞이지 않아야 한다. 사운드 선호 설정은 진행 초기화와 별도로 유지한다.

공유 품목은 기능 태그와 높이 조절 책상 자산·비교 UI를 재사용하는 수준이다. 임무 1과 임무 3의 학교 수요는 별도 구매이다. 첫 버전에는 시설 간 공용 물품 대여, 재고 공유, 재배치 운송, 실시간 주민 경제를 넣지 않는다. 이후 추가하려면 현 버전의 3임무 완성과 검증을 먼저 끝낸다.

## 11. 수치 검산 기록과 개발자가 재현할 검사

이 문서 작성 시 Node.js로 모든 적격 공급안 조합과 가능한 시작 슬롯을 전수 열거했다. 각 조합에 대해 시작 가능 시점, 연속 길이, 작업 충돌, 요구 마감, 예산을 검사했다. 임무 2는 초기 설치 이후의 재확인 시작 슬롯 1칸도 모두 열거하고 개선비 8을 포함했다.

검산 결과:

| 임무 | 적격 공급안 조합 수 | 예산·일정을 모두 충족하는 조합 수 | 유효 시간 배치 수: 공급안 순서 |
|---|---:|---:|---|
| M1 | 4 | 3 | L1+S1: 2 / L1+S2: 3 / L2+S1: 3 |
| M2 | 4 | 3 | I1+G1: 6 / I1+G2: 14 / I2+G1: 9 |
| M3 | 4 | 3 | P1+E1: 3 / P1+E2: 4 / P2+E1: 5 |

마지막 고가 조합은 각 임무에서 시간 배치가 가능하지만 예산이 8 초과한다. **공급안 조합 세 개가 모두 가능한 것이 검증됐다는 뜻이지 모든 임의 배치가 가능하다는 뜻은 아니다.** 관찰 분기의 문구 선택은 수치 검산과 별도이며 실제 UI 검증이 필요하다.

실행 시 사용한 검산 명령은 `node scripts/verify-mission-balance.cjs`이고 종료 코드 0과 세 임무 각각 유효 공급안 조합 3개를 확인했다. 이 검산은 제작 명세 검토용이며 배포 게임의 검증을 대체하지 않는다. 개발자는 실제 게임 데이터에서 같은 열거 검사를 테스트로 구현해야 한다.

필수 테스트:

1. 모든 요구에서 `safetyPass`와 필수 태그를 통과한 대안이 2개 이상이다.
2. 각 임무의 실행 가능한 전체 공급안 조합이 최소 2개이며 현재 데이터에서는 정확히 3개이다.
3. 도착 이전, 완료 마감 초과, 한 칸 겹침, 예산 1점 초과를 각각 차단한다.
4. 예산이 정확히 82/78/80인 정상 계획을 허용한다.
5. 길이 2를 시작 2에 놓으면 슬롯 2와 3만 점유한다.
6. 임무 2 개선비 누락, 개선 칸 누락, 초기 설치와 같은 칸의 재확인, 슬롯 6의 재확인을 차단한다.
7. 임무 2는 잘못된 개선 선택이나 관찰 생략 상태에서 완료 처리하지 않는다.
8. 계획 수정으로 기존 비용·점유 칸이 중복 누적되지 않는다.
9. 임무 재시작 시 다른 임무의 물품·관찰 완료 상태가 남지 않는다.
10. 실행 연출을 건너뛰어도 최종 판정은 동일하고, 필수 사용 확인은 남아 있다.
11. L0/S0/I0/G0/P0/E0의 비교·미리보기를 열 수 있다. 처음부터 숨김·비활성화하지 않으며, 잠정 선택 후에는 미충족 조건을 설명하고 확정을 막는다. 안전확인 미충족 안도 실행할 수 없다.
12. 두 적격 대안을 비교한 상태는 자동 기록된다. ‘읽었어요’ 버튼이나 선택할 때마다 확인창을 반복하는 경로가 없다.
13. L1/L2는 오전 독서→오후 프로그램의 공간 전환 방식이 다르다. S1/S2와 E1/E2는 소형 배치·넓은 상판의 사용 모습이 다르며, 모두 높이 조절·무릎 공간의 필수 기능을 갖는다.

## 12. 최종 수용 기준

### 기능과 전달

- 새 사용자가 도움 없이 첫 90초 안에 도서관 공간 전환의 필요를 보고 제시안의 사용 미리보기를 열어 조건을 확인한 뒤 공급안을 한 번 비교·선택한다. 부적격 안을 처음부터 비활성화해 답을 알려주는 흐름은 통과로 인정하지 않는다.
- 3임무를 모두 실제 플레이로 완료한다. 최저비용 조합과 예산을 정확히 사용하는 조합을 모두 한 번씩 확인한다.
- 시험 이용자에게 “무엇을 하는 게임인가?”라고 물었을 때 최소한 ‘필요에 맞는 물건/공급안을 비교해 공공시설에서 쓰게 한다’는 의미가 나온다. ‘배송하는 게임’, ‘직원 일정표 게임’만 나온다면 요구·비교의 비중을 수정한다.
- 임무 2 뒤에 사용자가 첫 구매와 시범사용, 관찰·개선의 흐름을 한 문장으로 말할 수 있다.
- 설치 칸 규칙을 잠시 제거한 종이 검토에서도 요구 적합성에 관한 선택 이유가 남는다. 도서관의 좁은 수납과 빠른 공간 전환, 학교의 소형 배치와 넓은 재료 전개라는 실제 사용상의 차이를 설명할 수 있어야 한다.
- 실제 법령·가격·성과로 오인될 수 있는 수치와 표현이 없다. 정책 사실과 창작 설정이 구분된다.

### 시각·사운드 품질

- 이미지 레이어가 실제로 사용되고, 네 시설의 시점·팔레트·광원이 일관된다.
- 핵심 한글·가격·버튼·표지는 DOM 텍스트이며 이미지 속 깨진 글자가 없다.
- 준비 전/후가 건물 색만이 아니라 사람의 행동·물품 이용·생활음으로 구별된다. 도서관은 오전 독서에서 오후 프로그램으로 실제 배치가 전환되고, 학교는 책상 높이 조절과 소형/넓은 상판의 사용이 보인다. 다른 품목을 다루던 과거 기획의 자산·효과음을 남기지 않는다.
- 시작, 비교, 배치, 실행, 결과에 대응하는 소리와 시각 피드백이 있다.
- 음소거·저동작·키보드만으로도 끝까지 플레이할 수 있다.
- 1280×720, 1440×900, 1920×1080에서 비교 패널·일정·확정 버튼이 잘리거나 겹치지 않는다.

### 전달·실행 안정성

- 최소 현재 Chrome과 Edge의 일반 PC 환경에서 시작·3임무 완료·재시작을 점검한다.
- 콘텐츠의 일부 폰트·오디오 로드가 늦어도 검은 화면으로 멈추지 않는다.
- 이미지는 목적 크기에 맞춰 압축하고, 주요 UI 상호작용에 눈에 띄는 지연이 없다.
- 플레이 중 외부 AI 서비스 호출·계정·결제·개인정보 입력을 요구하지 않는다.
- 게임 실행에 필요한 이미지·오디오·폰트의 사용 권한과 출처를 기록한다. AI 보조 제작 과정도 기록한다.
- 공모전용 약 1분 시연영상은 ‘요구 파악 → 비교 → 일정 조정 → 이용 변화 → 혁신제품 관찰·개선’을 보여준다. 지도 전경만 이어 붙이지 않는다.
