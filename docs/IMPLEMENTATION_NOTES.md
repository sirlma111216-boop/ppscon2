# 구현 기록 — 명세에서 정한 것과 구현하며 정한 것

작성: 2026-11-05. 게임 규칙의 기준은 [GAME_SPEC.md](GAME_SPEC.md), 시각 기준은 루트 [DESIGN.md](../DESIGN.md)다.
이 문서는 그 두 문서에 없어서 구현 과정에서 정한 내용과, 코드를 고칠 때 알아야 할 구조를 적는다.

`src/game`과 `src/audio/manifest.ts`, `src/assets/layout.ts`·`scenes.ts`는 브라우저 없이 Node에서 그대로 불러올 수 있게
지워지는 타입 문법만 쓰고 `.ts` 확장자로 서로를 가져온다. 테스트 도구를 따로 설치하지 않고 Node 24의 `node --test`를 쓴다.

## 명세에 없어 구현에서 정한 것

### 부적격 제시안의 비용·도착·설치 칸

명세는 L0·S0·I0·G0·P0·E0의 수치를 주지 않는다. 카드가 같은 서식을 쓰려면 값이 필요해 아래처럼 정했다.
이 안들은 확정할 수 없으므로 예산·일정 전수 검산(각 임무 실행 가능 조합 3개)에는 영향이 없다.

| ID | 비용 | 도착 | 설치 | 갖춘 필수 기능 | 빠진 필수 기능 |
|---|---:|---:|---:|---|---|
| L0 고정형 큰 테이블 | 28 | 1 | 1 | 없음 | 배치 전환, 수납 구역에 보관 |
| S0 고정 높이 책상 | 26 | 1 | 1 | 무릎 공간 | 높이 조절 |
| I0 음성 전용 안내 장치 | 46 | 1 | 1 | 개인정보를 모으지 않음 | 글자와 음성 안내 |
| G0 바닥 고정 안내판 | 12 | 1 | 1 | 알아보기 쉬운 그림 표지 | 옮길 수 있음 |
| P0 행사 장식 조형물 | 44 | 1 | 1 | 옮길 수 있음 | 그늘 제공 |
| E0 공유학습용 고정 높이 책상 | 32 | 1 | 1 | 무릎 공간 | 높이 조절 |

‘가장 싼 카드가 늘 부적격’이라는 요령이 생기지 않도록 I0·P0·E0는 두 적격 안 사이의 값으로 두었다.
명세의 공통 예시인 ‘안전확인 미충족’ 안은 화면 카드로 두지 않았다(요구당 카드 3장). 엔진은 `safetyPass`를 검사하며
테스트가 안전확인이 없는 가상의 안을 넣어 확정이 막히는 것을 확인한다.

### 조건 판정을 드러내는 시점

카드의 필수 조건 두 줄은 처음에는 ‘사용 모습을 보고 확인해요’로 보인다. 사용 미리보기를 열거나, 그 안을 잠정 선택하거나,
나란히 비교표를 열면 충족·불충족과 이유가 드러난다. 부적격 안도 처음부터 열려 있고 누를 수 있다.

### 비교 기록(`comparisonReviewed`)

요구마다 (1) 두 적격 안의 미리보기를 각각 열었거나 (2) 나란히 비교표를 연 경우 자동으로 기록한다. 확인 버튼은 없다.
기록이 없으면 그 요구의 ‘같은 기준으로 비교’ 10점이 빠지고, 결과 화면이 이유를 한 줄로 알려 준다.
같은 임무를 ‘다른 안으로 다시 계획’할 때는 이미 살펴본 기록이 이어진다.

### 이용 확인

실행이 끝나면 요구 두 개의 이용 장면을 차례로 본다. 장면을 본 뒤 ‘다음’으로 넘어가는 것이 확인이며, 건너뛰기를 눌러도 이 단계는 남는다.
임무 2의 주민센터는 고치기 전·후 화면과 재확인 문장을 함께 보여 준다.

### 실행 연출

단계 하나에 1.7초(개선·재확인은 2.6초), 동작 줄이기에서는 0.6배다. 가장 긴 계획도 관찰 대기를 빼면 24초 안에 끝난다.
결과는 확정 시점에 정해져 있고 연출은 그것을 보여 주기만 한다. 관찰 단계는 건너뛰기로 지나칠 수 없다.

### 저장

- 저장 시점: 임무 전환, 계획 변경(선택·칸·비교 기록), 계획 확정, 결과 확정.
- 실행·관찰·이용 확인 도중에 창을 닫으면 ‘확정 직후’로 저장돼, 이어할 때 같은 계획의 실행 처음부터 다시 본다.
- 결과까지 본 임무는 결과만 남고 이어하기는 다음 임무의 전환 화면에서 시작한다.
- 저장 버전이 다르거나 해석할 수 없으면 버리고 새로 시작할 수 있다. 소리·움직임 설정은 다른 키에 저장돼 새 게임에도 남는다.

### 화면 배치

- 데스크톱(1100px 이상): 위에 임무·예산·상태 문장·‘이 계획으로 진행’·설정, 가운데 무대, 오른쪽 요구·비교 패널, 아래 6칸 일정.
  무대 높이는 화면 높이에 맞춰 줄어들어 1366×768에서도 일정이 한 화면에 보인다.
- 그보다 좁으면 무대 → 패널 → 일정 → 확정 버튼 순서로 세로 배치한다. 시설을 열어 둔 동안에는 무대가 위에 붙어 있어
  카드를 읽으며 미리보기 장면을 함께 볼 수 있다.
- 상태 문장은 계획 검증의 첫 문제를 그대로 보여 준다. 문제가 있는 칸에는 ‘겹침·도착 전·마감 뒤·관찰 전’ 표시가 붙는다.

### 그림

- 전용 그림이 없는 여섯 부적격 안과 학습 재료·해는 `src/components/GenericProp.tsx`의 작은 SVG 조각 그림으로 그렸다(그림 팔레트만 사용).
- 높이 조절은 책상 그림을 늘이지 않고, 같은 그림의 상판 쪽 절반만 위로 올려 표현한다.
- 접이식 테이블의 접힘은 가로로 좁혀 수납 구역에 세우는 동작으로 표현한다.
- 지도 위 건물 위치는 매니페스트의 접지점 값을 그대로 쓴다. 시설 장면 속 물품·주민의 자리는 `src/assets/scenes.ts`에서 정했다.
- 주민 그림 둘레의 번진 광륜과 물품 둘레의 흩어진 자국은 파생본을 만들 때 낮은 알파를 지워 정리했다. 원본은 고치지 않았다.
  대응표: [IMAGE_DERIVATIVES.md](IMAGE_DERIVATIVES.md)

## 검사 방법

```sh
npm run check      # 타입 검사
npm test           # 규칙·상태·저장·그림 연결 검사
npm run build      # 타입 검사 + 빌드
npm run preview    # 빌드 결과 확인용 서버
node scripts/e2e-playthrough.mjs --url http://localhost:4173 --out <화면 저장 폴더>
```

자동 플레이 스크립트는 가려진 버튼, 화면 가로 밖으로 나간 버튼, 가로 넘침, 콘솔 오류, 실패한 요청, 준비되지 않은 음원 요청을
문제로 보고한다. 옵션은 파일 첫머리에 있다. 실제로 돌린 환경과 결과는 [DELIVERY_STATUS.md](DELIVERY_STATUS.md)에 적는다.
