## 구현된 것

- **수요 → 비교 → 선택 → 일정 → 실행 → 이용 확인 → 결과**의 흐름이 세 임무 모두에서 이어진다.
- 요구마다 공급안 카드 3장(적격 2, 부적격 1). 부적격 안도 처음부터 열려 있고, 잠정 선택하면 이유를 알려 주되 확정은 막힌다.
- 사용 미리보기: 건물 그림 위에 물품·주민 그림을 얹은 장면이 두 순간(예: 오전 독서 ↔ 오후 프로그램)으로 바뀐다.
  접이식은 접어 수납 구역에 세우고, 이동 모듈은 밀어 모은다. 소형 책상은 간격이 넓고, 넓은 책상은 재료를 펼친다. 높이는 책상마다 따로 올라간다.
- 준비 일정 3일 × 2칸. 클릭으로 놓고 옮기며(끌어다 놓기는 보조), 겹침·도착 전·마감 뒤·관찰 전을 칸과 상태 문장으로 알려 준다.
- 임무 2: 개선·재확인 8점과 한 칸이 처음부터 보인다. 설치 뒤 이용자의 망설임을 관찰하고, 개선 두 가지 가운데 하나를 고르고, 공급자가 고친 뒤 다시 확인한다.
  맞지 않는 개선은 다시 고를 수 있고 예산·일정·점수에 남지 않는다. 건너뛰기로 지나칠 수 없다.
- 결과: ‘요구 2/2 충족 · 확인 2/2 · 사용 예산 70/82’와 선택 근거, 학습 완료 표시(60/20/20), ‘다른 안으로 다시 계획’.
- 엔딩: 네 시설을 이번 플레이의 선택으로 되짚고, 두 가지 의미를 짧게 정리한다.
- 저장·이어하기(이 기기의 브라우저), 임무 다시 계획, 새 게임, 마친 임무 다시 열기.
- 설정: 전체 음소거, 음악·효과음·환경음 음량, 동작 줄이기. 소리가 없어도 모든 안내가 화면에 보인다.
- 화면 크기에 따른 재배치(데스크톱 2단, 그보다 좁으면 세로 배치).

명세에 없어 구현하며 정한 내용(부적격 안의 수치 등)은 [IMPLEMENTATION_NOTES.md](IMPLEMENTATION_NOTES.md)에 있다.

## 실제로 한 검사

### 자동 검사

- `npm run check`, `npm test`, `npm run build` 통과. 테스트는 명세 11장의 필수 검사를 옮긴 것으로,
  각 임무의 실행 가능 조합이 정확히 3개이고 배치 수가 명세의 검산표(2·3·3 / 6·14·9 / 3·4·5)와 같은지 전수 열거로 확인한다.

### 실제 브라우저 자동 플레이

`scripts/e2e-playthrough.mjs`가 헤드리스 브라우저에서 마우스 또는 키보드 입력으로 인트로부터 엔딩까지 진행했다.
대상은 빌드 결과물(`npm run build` → `npm run preview`)이다.

| 브라우저 | 화면 | 조합 | 입력 | 연출 | 결과 |
|---|---|---|---|---|---|
| Chrome 156 | 1366×768 | 최저비용(70·66·68) | 마우스 | 전체 재생 | 엔딩까지 완료, 문제 0건. 실행 연출 12.3초 / 18.9초(관찰 선택 시간 포함) / 12.7초 |
| Chrome 156 | 1920×1080 | 예산 전액(82·78·80) | 키보드만 | 전체 재생 | 엔딩까지 완료, 문제 0건. 실행 연출 10.5초 / 17.5초 / 11.4초 |
| Chrome 156 | 390×844 | 예산 전액 | 마우스 | 건너뛰기 | 엔딩까지 완료, 문제 0건 |
| Chrome 156 | 768×1024 | 최저비용 | 마우스 | 건너뛰기 + 동작 줄이기 | 엔딩까지 완료, 문제 0건 |
| Edge 156 | 1366×768 | 최저비용 | 마우스 | 건너뛰기 | 엔딩까지 완료, 문제 0건. 브라우저의 캡처가 멈춰 화면 6장은 저장하지 못함 |

‘문제 0건’은 콘솔 오류·경고, 실패한 요청, 가로 넘침, 가려진 버튼이 없었다는 뜻이다.
이 표는 마지막 빌드에서 돌린 결과이며, 그 전에 개발 서버와 이전 빌드에서도 같은 스크립트를 여러 번 돌리며 화면을 고쳤다.

스크립트가 진행하며 확인한 것:

- 누르려는 버튼이 다른 요소에 가려져 있거나 화면 가로 밖에 있으면 실패한다. 가로 넘침, 콘솔 오류·경고, 실패한 요청도 문제로 센다.
- 첫 화면의 주 버튼은 하나이고, 저장이 없으면 ‘이어하기’가 없다. 빈 계획·부적격 안·예산 초과로는 확정할 수 없다.
- 카드 3장이 모두 눌리고, 살펴보기 전에는 조건 판정이 보이지 않는다. 부적격 안을 고르면 이유가 나온다.
- 겹침, 관찰 전 재확인, 예산 8점 초과를 일부러 만들고 안내 문장을 확인한 뒤 고친다.
- 임무 2에서 건너뛰기를 거듭 눌러도 관찰에서 멈춘다. 맞지 않는 개선을 고르면 안내가 나오고 다시 고를 수 있다.
- 연출을 건너뛰어도 이용 확인 두 장면이 남는다. 결과 요약과 학습 완료 표시(100/100)가 기대값과 같다.
- 임무 1 뒤 새로고침 → ‘이어하기’로 임무 2가 열린다. 엔딩 뒤 마친 임무 다시 열기 → 다시 계획 → 새 게임 → 처음 화면.
- 준비되지 않은 음원 파일과 원본 PNG를 한 번도 요청하지 않았다.

### 화면을 보고 확인한 것

자동 플레이가 남긴 화면을 Claude Code가 열어 보고 다음을 확인·수정했다. **사람이 본 것이 아니다.**

- 인트로·임무 전환·결과·엔딩에서 글이 그림의 빈 종이 영역 안에 들어가는지
- 도서관의 두 적격 안이 오후 배치에서 서로 다르게 보이는지, 학교 책상의 높이 차이와 재료가 보이는지
- 주민센터 관찰 장면과 고치기 전·후 화면, 공원 안내판의 자리 옮김, 그늘막 아래 주민
- 1366×768에서 상단 바·무대·요구 패널·6칸 일정이 한 화면에 들어오는지
- 390×844와 768×1024에서 카드·일정·확정 버튼이 가려지지 않는지

### 계산으로 확인한 것

- 주요 글자·버튼 색 조합의 명도 대비는 모두 4.5:1 이상이다(보조 글자 5.0~6.5, 주행동 버튼 6.3, 청록 버튼 6.0).
  색상값으로 계산한 수치이며, 그림 위에 얹힌 글자를 화면에서 측정한 것은 아니다.

## 확인하지 못한 것

- **소리.** 음원이 없어 재생·겹침·음량·반복 이음매를 확인할 수 없었다. 남은 검증은 [AUDIO_HOOKUP.md](AUDIO_HOOKUP.md) 끝에 있다.
- **사람.** 실제 사람의 플레이, 첫 90초 안의 첫 선택, 게임의 뜻이 전달되는지는 확인하지 않았다.
- **키보드 Tab 순서 전체와 화면낭독기.** 자동 플레이의 키보드 모드는 버튼에 초점을 준 뒤 Enter로 누르는 방식이라,
  모든 조작이 초점·Enter로 가능한 것은 확인했지만 Tab으로 도는 순서의 편의는 사람이 확인해야 한다.
- **200% 확대, 브라우저 글자 크기 변경.** 좁은 화면 배치는 확인했지만 확대 상태 자체는 시험하지 않았다.
- **Chrome·Edge 밖의 브라우저**(Safari, Firefox)와 실제 휴대전화·태블릿 기기.
- **느린 네트워크·그림 로딩 실패.** 그림이 늦게 와도 글과 버튼은 DOM이라 진행은 되도록 만들었지만, 조건을 걸어 시험하지는 않았다.

## 알려 둘 점

- 원본 PNG(약 31MB)가 `public/assets/images`에 그대로 있어 배포본에도 포함된다. 게임은 불러오지 않고 `#dev-assets` 자료실만 쓴다.
  공모전용 실행 ZIP의 크기를 줄이려면 원본을 `public` 밖으로 옮기고 자료실을 개발 전용으로 바꾸는 방법이 있다.
- 이미지 파생본을 만드는 `sharp`가 개발 의존성에 추가됐다. 빌드에는 쓰이지 않고 `npm run assets`에서만 쓴다.
- `.claude/launch.json`은 Claude 데스크톱 앱의 미리보기 서버 설정이다. 게임 동작과 무관하다.
- Edge 헤드리스에서는 브라우저의 화면 캡처 명령이 가끔 응답하지 않는다. 1920×1080 키보드 플레이가 이 때문에 두 번 중단됐고,
  그 뒤 스크립트를 캡처가 멈추면 그 장만 건너뛰고 진행하도록 고쳤다. 게임 진행과 판정은 Edge에서도 끝까지 통과했지만
  Edge에서의 **키보드만** 플레이는 끝까지 확인하지 못했다(같은 조합은 Chrome에서 통과).
